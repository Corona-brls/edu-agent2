## 3. 对强制质疑项的裁决

### 3.1 外部失败不能归并为单一原因

批准的修复必须分别处理：

1. paper/NVD/standard 单来源未进入 `GroundedSpanAnswer`；
2. paper authors 与 standard 状态字段未进入模型可见证据；NVD字段已经完整，不得误修；
3. multi-source attempt 0 的可信 DOI 被 arXiv-only 规则误拒；
4. multi-source attempt 1 只确定为 `ValidationError/response_parse`，具体字段不可恢复；只补安全可观测性和严格失败测试，不修改 `GroundedSpanAnswer` Schema、不猜字段、不放行 attempt 0。

### 3.2 单来源结构化范围

`_requires_grounded_answer()` 只能在以下条件成立时返回 true：

- intent 不是 Practice；
- `required_sources` 经现有归一化后明确包含 `paper`、`vulnerability`、`standard` 或 `project` 至少一种；
- `_answer()` 的既有 missing-source 门已确认所需来源实际存在。

纯 course、Practice、innovation 非外部事实路径不得因“已有任意 evidence”进入该分支。

9B 的计划在此处增加一条有约束力的实施细化：`_answer_evidence()` 对外部 grounded 请求必须只带入显式 required source 类型的可信 evidence；单一类型可以保留该类型的多个候选，不能只为通过测试固定一条；若同时明确要求 course，则只加入当前课程已授权证据。不得把初始检索得到但未请求的 course 或其他外部类型混入模型目录。现有多来源“每个类型选择最相关可信项”的语义可保留。

### 3.3 字段来源

- paper authors 只能取现有资源记录的结构化 `authors` 字段，不能从摘要、模型输出或任意 raw 文本猜测。元素数量、单项长度和总长度必须有界，并经过既有净化。
- standard 只能白名单读取 `raw_metadata.version`、`official_metadata_only`、`local_uploaded`、`local_verification_status`；布尔值和状态必须按服务器值渲染。
- NVD 的 `cvss`、`cwe`、`published`、`lastModified` 路径保持原样，增加回归断言而不改映射。
- 字段缺失时省略或明确“来源未提供”，模型不得补写。

### 3.4 DOI 的窄范围兼容

DOI通过必须同时满足：

1. EvidenceItem 是当前 run 的可信 `paper`；
2. 已通过现有 trusted/provenance、HTTPS、content_hash 门；
3. claim 绑定服务器目录中的同一 source_id 与精确 `external_id` span；
4. external_id 是有界、锚定的 DOI 语法，canonical DOI 与 span 值相等；
5. 只允许大小写、可选 `doi:` 前缀的受控等价，不从 URL、title、claim 或模型自报字段推导 DOI。

伪造 DOI、错资源类型、错 source/span、仅 URL 含 doi.org、前后附加事实均继续拒绝。不得修改通用 support/relevance/token 阈值。

### 3.5 source/span/quote 与required-source覆盖

模型仍只提出 `claim_text/source_id/evidence_span_id`；服务器校验 span存在、source归属、renderer顺序、精确quote、支持性、相关性、重复项和required-source覆盖。不得静默改写claim、替换span、删除失败来源或让服务器生成事实。

标准的 title/external_id/text 模板只能支持标准编号、版本、官方链接、metadata-only及本地核验状态。不得支持条款正文、标准要求或“官方全文已核验”等额外事实。

### 3.6 retry与第二候选解析失败

- attempt 0 后最多一次 attempt 1；复用相同 EvidenceItem 和 EvidenceSpan 集合。
- retry不得调用Planner、retrieve、Connector、MCP或真实工具。
- Guard首失败的服务端安全tuple必须实际进入传给DeepSeek客户端的messages；仅写metadata不算通过。
- 通用failure tuple只含 attempt、error_code、ordinal、source_id、span_id、claim长度/哈希和规范化标志。
- `ValidationError`只允许记录至多8个 `{loc,type}` 和根异常类；禁止保存 `msg`、`input`、`ctx`、candidate或完整异常字符串。
- attempt 1解析失败时保持attempt 0的Guard拒绝语义，额外记录`response_parse`；不得捕获异常后接受attempt 0，也不得第三次生成。
- 首候选自身无法解析或provider失败时直接使用现有模型失败/安全拒答语义；外部grounded路径禁止Template成功fallback。
- `backend/llm/schemas.py`不在白名单。当前严格Schema不是已证实缺陷，不能因不可恢复的ValidationError而修改。

### 3.7 Citation.source_id兼容

`backend.schemas.Citation`增加兼容旧对象的可选 `source_id`（建议 `str | None = None` 并限制为服务器source格式）；这是响应的加法字段。兼容仅意味着旧对象可以缺失，新 `_to_chat_response()` 的每一项必须始终传入非空 source_id。

前端规则：

- source_id存在时原样显示，例如只剩S2时卡片仍为`[S2]`；非连续、缺号是正确表现。
- 只有历史响应确实缺字段时，才允许当前位置fallback。
- 同一Citation的source_id、document_id、chunk_id、URL和resource_type必须来自同一EvidenceItem。
- 禁止为了连续显示而重编号正文或卡片，禁止只改视觉标签。

### 3.8 创新来源

裁决维持 `NO_CHANGE_CONFIRMED`。9E必须使用固定topic/current_plan，并在正常产品流程中准备相关可信案例。空可信结果应给出诚实空状态或归类为内容/第三方限制；不得纳入不相关GitHub项目。9D不得修改innovation文件或测试期望来强制非空。

### 3.9 `/teacher`入口

`frontend/pages/teacher.py`作为Streamlit pages文件存在，`render()`已在读取业务数据前检查token和角色；问题是文件直接执行时没有调用它。允许增加 `if __name__ == "__main__": render()`。主应用以模块导入后显式调用`teacher.render()`，模块名不是`__main__`，因此不会双重渲染。必须以AppTest/等价前端测试证明匿名直接页显示登录门且没有教师业务API调用。

## 6. 冻结红绿测试矩阵

### 6.1 旧实现稳定失败的红测

1. 单paper、NVD、standard、project required source均断言调用 `generate_structured(..., GroundedSpanAnswer)`；旧实现前三类不满足。
2. 单外部路径只把明确要求的可信类型放入evidence/span目录；未请求course或其他外部类型不进入。
3. paper authors与standard状态字段可形成受控text spans；NVD字段映射快照不变。
4. 当前run可信paper的精确DOI身份claim通过；伪造、错类型、错source/span、URL推导和附加事实拒绝。
5. multi attempt 1返回结构错误时，最终拒答，不恢复attempt 0；只记录安全`loc/type`。
6. S2过滤为唯一Citation时，API仍输出source_id=S2，前端显示`[S2]`。
7. 匿名直接执行teacher page显示登录提示；旧实现为空。

### 6.2 定向绿测

- paper：标题、authors、摘要线索、arXiv和DOI；来源不含authors时不生成作者。
- NVD：CVE、描述、CVSS、CWE、发布时间和官方链接；不生成利用步骤。
- standard：编号、版本、metadata-only、本地核验状态和官方链接；条款/全文事实负例必须拒绝。
- project：GitHub正对照迁移至结构化路径且不执行代码。
- multi-source：paper/vulnerability/project覆盖；合法DOI；相同证据只生成retry，工具计数不变。
- 实际客户端messages：attempt 1包含安全首失败反馈，hash与attempt 0不同。
- 两次候选失败、首候选parse失败、第二候选ValidationError均安全拒答且无Template成功。
- Guard负例：unknown source/span、source mismatch、quote mismatch、overreach、duplicate、missing required source、prompt injection、非HTTPS/缺provenance。
- Citation：单S2、多个非连续source、legacy无source_id、source与document/chunk一致。
- teacher：匿名无API、学生无管理数据、主应用教师导航只render一次。

### 6.3 共享兼容性回归

只运行、不修改：Practice全套和course+paper、course-only、Flow 03、Flow 08、证据不足、权限、prompt injection、resource portal、innovation、auth/RBAC、phase3 e2e及现有Citation Guard测试。

生成retry必须证明Planner、retrieve、MCP、Connector和真实工具调用数均不增加；不得只断言最终字符串。

### 8.3 PASS/FAIL

- innovation：使用`5G NAS authentication`固定输入，至少一条正常产品流程获得的相关可信案例，来源可展开；若前置内容不存在则记录`CONTENT_GAP/THIRD_PARTY_LIMITATION`，不是代码失败也不能宣称通过。

每项立即保存简洁的原始页面、run/trace、工具/候选/Guard摘要和`result.json`。不要求ZIP、集合指纹、固定文件数、目录总哈希，也不得删除历史失败或既有PASS。
