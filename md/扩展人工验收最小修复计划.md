## 4. 外部 grounding 详细设计

### 4.1 路由和 evidence/span

1. Connector/MCP 已成功取得可信资源的链路保持不变，不重新开发，也不在生成 retry 时重新调用。
2. 单来源 paper、NVD、standard、project 与多来源请求使用同一服务器控制的 `EvidenceSpan` 目录；模型只能选择目录中当前 run 的 source_id/span_id。
3. `required_sources` 中每种明确请求的外部来源至少由一个通过 Guard 的 claim 覆盖；未知来源、类型不匹配、缺 provenance、非 HTTPS、空 content_hash 或当前 run 未观察到的 evidence 继续拒绝。
4. GitHub 单来源虽在 9A 正对照中通过，仍迁移到同一结构化契约并作为回归，不把一次启发式成功泛化为正确实现。
5. 课程、Practice 和混合 course+external 的既有授权、水合、完整性预检和 Guard 不变。

### 4.2 字段映射边界

- paper `authors` 只来自可信 Connector 结构化字段，按现有净化规则处理并设定元素数量/单项/总长度上限；模型不得自行补作者。
- NVD 映射完全保留，测试用于证明未回归，不新增猜测字段。
- standard 只暴露已有元数据和本地全文状态；`official_metadata_only=true` 或没有已核验本地全文时，回答必须明确“仅元数据/无已核验全文”，不能生成条款内容。
- 若请求字段在来源中不存在，答案应省略或明确来源未提供，而不是自由生成。

### 4.3 DOI 窄兼容与 Guard

- DOI 兼容只适用于由现有可信论文工具链产生、当前 run 已验证且位于 `external_id` span 的 DOI。
- DOI 规范化只允许大小写及 DOI 前缀的受控等价处理；最终 canonical DOI 必须与 span 值一致。
- 不能因 URL 中出现 `doi.org`、模型自报“trusted”或任意 `10.` 前缀就放行。
- arXiv、CVE、仓库身份规则继续独立；通用支持性、相关性、重复、source/span mismatch 与 required-source coverage 全部保持 fail closed。

### 4.4 retry、错误语义与可观测性

1. 最多两个候选：attempt 0 加至多一次 attempt 1。
2. attempt 1 只重做最终结构化生成；Planner、Connector、MCP、检索和工具调用计数不得增加。
3. Guard 首失败反馈由服务端生成并真正进入 provider messages；包括有界的 error_code、ordinal、source_id、span_id 和处理指令，不含正文。
4. attempt 1 响应解析出现 `ValidationError` 时，只保存至多 8 个 `{loc,type}` 项和根异常类型；9A 未恢复具体失败字段，计划不得预设字段或围绕猜测硬编码。
5. attempt 0 Guard 失败而 attempt 1 解析失败时，最终仍为 fail-closed：保留首个 grounding 错误作为对外拒答语义，并在 model-call/trace 中独立记录 `response_parse`；不得第三次生成。
6. 首次 DeepSeek 调用即 provider/解析失败时返回现有批准的模型失败/安全拒答语义；Template 不得生成一个看似成功的 grounded 外部回答。
7. 不记录 API key、Authorization header、完整 prompt、candidate、claim、chunk、Connector 私有正文或 Pydantic `input/ctx`。

## 5. 引用显示端到端契约

数据流固定为：

`final_answer marker [Sx]` → `_to_chat_response()` 按被引用 source 过滤 → `_citation_from_evidence()` 保留同一 `source_id` → `Citation.source_id` → FastAPI JSON → `_render_citations()` 显示同一 `[Sx]`。

通过标准：

- 如果正文只引用原始 S2，响应中的唯一 Citation 仍是 `source_id=S2`，卡片显示 `[S2]`。
- document_id、chunk_id、URL、resource_type 和 source_id 必须属于同一个 EvidenceItem。
- 不强制 source_id 连续；过滤后的 `[S2]` 单卡片是正确行为。
- legacy 响应缺 source_id 时才允许前端位置 fallback，且不得反向改变正文或来源绑定。
