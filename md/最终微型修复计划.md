# A. 反向技术评审结论

## A1. 上一版遗漏的问题

上一版计划遗漏了一个已被当前代码确认的会话隔离风险。

[frontend/app.py:14](</C:/Users/Asd/Desktop/edu agent/frontend/app.py:14>) 调用 `_render_login()` 后，即使没有登录也继续渲染学生页面；[frontend/app.py:143](</C:/Users/Asd/Desktop/edu agent/frontend/app.py:143>) 的 `_clear_auth_session()` 只删除：

- `auth_token`
- `current_user`
- `client_session_id`

但没有清理：

- `last_chat_result`
- `last_guide_result`
- `resource_search_payload`
- `resource_search_fingerprint`
- `assignment_context`
- `innovation_session`
- `selected_course_id`
- 后续新增的回答历史

这可能导致同一个浏览器会话退出后仍保留上一账号的页面结果。后端匿名请求仍会返回 401，因此它属于**前端会话数据隔离和显示缺陷**，并非后端越权，但必须修复。

此问题并入 R2，不新增第四个代码批次。

## A2. fallback 计划需要修正

当前有两个方向相反的问题：

1. Planner 失败后实际采用确定性策略，但没有标记 fallback。
2. 检索直接失败或课程范围检查失败后直接拒答，没有执行替代方案，却被标记为 fallback。

代码证据：

- Planner 确定性替代路径：[orchestrator.py:237](</C:/Users/Asd/Desktop/edu agent/backend/agent/orchestrator.py:237>)
- 检索异常误标 fallback：[orchestrator.py:592](</C:/Users/Asd/Desktop/edu agent/backend/agent/orchestrator.py:592>)
- 真正执行本地关键词替代：[orchestrator.py:654](</C:/Users/Asd/Desktop/edu agent/backend/agent/orchestrator.py:654>)
- 响应汇总：[orchestrator.py:1077](</C:/Users/Asd/Desktop/edu agent/backend/agent/orchestrator.py:1077>)

最终定义必须固定为：

> `fallback_used=true` 表示当前 run 中至少有一个组件实际采用了替代执行路径。

因此：

| 场景 | fallback_used |
|---|---:|
| DeepSeek 决策和生成成功 | false |
| Planner 失败，确定性策略接管 | true |
| DeepSeek 生成失败，TemplateProvider 接管 | true |
| 向量检索无结果，本地关键词检索接管 | true |
| 显式使用 TemplateProvider | true |
| 工具失败且没有替代方案 | false |
| Retriever 异常后直接拒答 | false |
| 跨课程证据校验失败后直接拒答 | false |
| MCP 失败后使用可信旧缓存 | true |
| `ask_user→continue` | 汇总同一 run 全部历史步骤 |

- 不关闭 Citation Guard；

- 不允许“工具成功”直接绕过逐事实引用检查。

此前浏览器供应器不可用属于环境限制，但 B1 已经通过 Codex 内置浏览器完成真实操作。
